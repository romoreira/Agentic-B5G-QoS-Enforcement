## 2. Experimental goal

The goal is to compare classical QoS control baselines against a policy constrained LLM based controller for a five slice B5G UPF scenario.

The experiment validates whether a realtime agentic loop can observe UPF telemetry, choose a QoS action, validate the action, and apply it through PFCP session modification without breaking the datapath.

The full control loop is

```text
TRex traffic phase
UPF and BESS telemetry snapshot
telemetry delta computation
candidate MBR action generation
LLM decision through vLLM
policy validation
pfcpsim session modify
new UPF state
```

The agent is not allowed to execute arbitrary actions. It selects from candidate MBR vectors generated by the controller, and every selected vector is validated before it is applied.

```text

If the campaign is repeated on an RTX6000 or H100, keep the same scripts and change the metadata accordingly.

Run the full agentic campaign with ten repetitions

```bash
#!/usr/bin/env bash
set -euo pipefail

CAMPAIGN_ROOT="$HOME/agentic_qos_results/campaigns/campaign_20260511_agentic_rtx6000_realtime_5slices"
EXP_DIR="$CAMPAIGN_ROOT/e4_agentic_rtx6000_realtime"

reset_mbr() {
  echo "[INFO] Resetting MBR to initial vector"
  python3 "$HOME/agentic_qos_scripts/agentic_apply_once.py" --reset || true
}

trap reset_mbr EXIT INT TERM

reset_mbr
rm -rf "$EXP_DIR"

for RUN in $(seq -w 1 10); do
  echo "============================================================"
  echo "[INFO] Starting run_${RUN}"
  echo "============================================================"

  python3 "$HOME/agentic_qos_scripts/run_agentic_realtime_run1.py" \
    --window-sec 10 \
    --windows-per-phase 6 \
    --run-name "run_${RUN}"

  python3 "$HOME/agentic_qos_scripts/analyze_agentic_realtime_run.py" \
    --run-dir "$EXP_DIR/run_${RUN}"

  reset_mbr

  echo "[INFO] Finished run_${RUN}"
done

find "$EXP_DIR" -maxdepth 1 -type d -name 'run_*' | sort | wc -l
```

## 13. Main preliminary insight

The agentic loop is operationally viable.

It successfully connected realtime UPF telemetry, LLM decision making, action validation, and PFCP based QoS modification. Across 240 decisions, no tool application failures were observed.

However, the agentic controller still needs stronger stateful damping or hysteresis. The LLM consistently selected valid actions, but the candidate policy allowed oscillatory behavior between adjacent MBR vectors in phases B and C. The recovery phase also generated fallbacks when the model selected the current vector while describing a modification.

Paper ready interpretation

```text
The policy constrained LLM controller was able to operate the UPF safely and apply valid QoS actions without tool failures. Nevertheless, the first realtime implementation exposed a stability gap. The controller reacted to overload, but oscillated between neighboring MBR candidates, suggesting that LLM based QoS control should be combined with explicit hysteresis, cooldown rules, or stateful damping before being deployed as a stable closed loop policy.
```

## 14. Recommended next experiment

The next campaign should keep the same model and traffic phases but add hysteresis.

Suggested E5

```text
e5_agentic_rtx6000_hysteresis
```

Suggested changes

```text
minimum dwell time before changing MBR again
no upward change inside overload phases
deterministic recovery in phase D
normalize mbr_kbps equal to current_mbr_kbps as keep
log oscillation_count as first class metric
```

This E5 campaign would directly test whether the instability observed in E4 is caused by policy candidate design rather than by the LLM API or UPF toolchain.
